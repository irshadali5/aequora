# Security Policy

Do not open a public issue containing a vulnerability, credential, private key, production endpoint,
or tenant data. Report suspected vulnerabilities privately to the repository owner/security contact
configured by the deployment organization. Include affected version/commit, impact, minimal
reproduction, and whether active exploitation is suspected, without including real secrets or
customer data.

Maintainers should acknowledge, triage severity, preserve evidence, create a sanitized regression
test before closure, update `docs/security-threat-matrix.md` for new abuse cases, and coordinate
release/advisory timing. Supported production versions and response-time commitments are set by each
distributor; this source repository does not claim a certification or universal SLA.
